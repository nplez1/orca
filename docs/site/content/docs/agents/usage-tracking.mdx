---
title: Usage & rate-limit tracking
---

Orca fetches usage for Claude Code, Codex, Gemini, OpenCode Go, Kimi Code, MiniMax, Grok, Antigravity, Cursor, GLM Coding Plan, DeepSeek, and Fireworks.ai and surfaces it in the status bar, so you know how close you are to a rate limit before an agent stalls.

## What's shown

- Current usage against the active account's plan.
- Time to reset for 5-hour, daily, weekly, and Claude Fable weekly windows (where applicable).
- A warning chip when you cross 80% of a limit.
- A money amount rather than a percentage for DeepSeek and Fireworks.ai, which publish no percentage quota.
- A monthly allowance bar for enterprise and usage-billed plans, which report a spending ceiling instead of 5-hour and 7-day windows.

## How it works

Orca asks each provider for your usage over the network, using the login that agent already has or a key or session cookie you add in Orca Settings.

For Claude, Orca requests `https://api.anthropic.com/api/oauth/usage` with the token from your existing Claude Code login; it does not ask for extra credentials. Triggers include:

- Once the Orca window is active after startup, then about every 15 minutes while it stays visible and focused.
- Bringing the window back to the front when the last check is more than 5 minutes old (sooner after a failed check).
- Switching the active Claude account or the runtime it runs in.
- Refreshing usage from the **Usage** popover or a Settings control that refreshes all usage, or changing OpenCode Go, MiniMax, or GLM Coding Plan usage credentials or settings. These refresh every provider, Claude included.
- Expanding the account list in the status bar's Claude account switcher, which fetches your other saved Claude accounts. The list opens expanded when an account needs sign-in.
- Orca Mobile or the web client connecting to this host or refreshing usage, which also fetches your other saved Claude accounts.

## Multi-account accounting

The status bar always reflects the _active_ account. Other configured accounts are visible in the account switcher with their own usage.

## Usage roster

Click the usage segment in the status bar to open the **Usage** popover. It lists every tracked provider (icon · name · plan · soonest reset · per-window bars), sorted so the tightest limit is first. DeepSeek and Fireworks.ai rows show a money amount instead of bars. Use the header refresh control to fetch usage again.

- **Detailed** — full bars, labels, and percentages for every window
- **Compact** — only the tightest window per provider

Under [Settings → Appearance](/docs/settings), choose **% used** vs **% remaining** for how those numbers read.

Rows without live numbers show a short status instead: **Loading usage…**, **not signed in**, **Usage unavailable**, **No usage data**, or a provider-specific error. Claude and Codex rows can drill into account switching; **Manage accounts** opens Settings.

### Mobile

On the companion app, open the host **Accounts** screen for the same switcher/usage readout. When Codex has earned **rate-limit reset** credits, spend one from that screen (see [Mobile companion](/docs/mobile)).

## API-key providers

DeepSeek and Fireworks.ai are configured with an API key in [Settings → Accounts](/docs/settings). Neither takes a CLI install or a sign-in, and neither publishes a percentage quota, so their rows read as a money amount rather than a bar.

- **DeepSeek** — your account **balance**, with granted and topped-up amounts broken out. DeepSeek publishes no historical usage or cost API, so there is no usage-over-time view, no token counts, and no percentage of quota. The balance may be denominated in CNY or USD depending on the account.
- **Fireworks.ai** — your **remaining credit balance**, with the current billing period's rated spend broken out beneath it. Orca discovers the account ID from the API key, with an optional manual override. Fireworks rates spend at the account level, and it can differ from the final invoice once credits or adjustments are applied.

  The balance comes from Fireworks' control-plane gateway rather than a published API — they expose credit only in their dashboard. If that call cannot be reached, the row falls back to showing the period's spend on its own, so the readout never goes blank.

## Enterprise and usage-billed plans

Some plans report a spending ceiling rather than 5-hour and 7-day quota windows. When the active account reports no such window, Orca shows the ceiling's own percentage as a monthly bar, and the detail panel shows the amounts consumed against it.

- **Claude** — the monthly spend cap, as a percentage bar with no countdown, because Claude does not report when this cap resets. The dollars consumed against the cap come from the same extra-usage balance the Usage credits section renders, so the two cannot disagree.
- **Codex** — the account's spend control, e.g. `10,048 of 52,000 credits`, with the reset date reported by the provider.
- **GitHub Copilot** — the credits consumed this month against the enterprise's monthly AI-credit budget, e.g. `412,300 of 1,000,000 AI credits`. GitHub's budget API reports that ceiling in dollars, so Orca displays it in AI credits using the price from the usage report.

  Orca reads this through the **GitHub CLI** you are already signed in to, which supplies both the credential and the enterprise slug. The scopes matter: `read:enterprise` is what exposes an enterprise's slug and `manage_billing:enterprise` is what reads its billing data, so a `gh` sign-in without them cannot serve this provider — Settings → Accounts shows the exact `gh auth refresh` command when that is the case. For accounts the CLI cannot serve, that section also accepts a token and enterprise slug directly, which is the override and takes precedence.

The percentage is normally the figure the provider itself reports, so it matches what their console shows. Two exceptions: GitHub Copilot reports only the dollar ceiling and the credits consumed, so Orca derives the percentage from those; and Claude derives it from the amounts whenever its payload carries no percentage, which includes a `spend` object with no `percent` and a legacy `extra_usage` figure reported as a 0–1 fraction rather than a percentage.

## Estimated cost (Stats)

The Stats breakdown may show **estimated cost** for known model families (including Claude 5-class and Codex GPT-5.6 rows). Rows marked **• inferred pricing** use Orca’s local price table, not a live bill from the provider. Prefer the provider console for authoritative spend.
